## 1. Item 0 — A2A v1.0 Wire Upgrade

**Authoritative:** ADR 0005 + A2A v1.0.1 spec at
https://a2a-protocol.org/dev/specification/.

The full JSON-RPC method surface after v1.1:

| Method (PascalCase) | Source | Notes |
|---|---|---|
| `SendMessage` | A2A § 9.4.1 | replaces v0.1.0 `message/send` |
| `SendStreamingMessage` | A2A § 9.4.2 | replaces v0.1.0 `message/stream` (SSE body) |
| `GetTask` | A2A § 9.4.3 | replaces v0.1.0 `tasks/get` |
| `ListTasks` | A2A § 9.4.4 (new in v1.0.1) | paginated; reads `TaskRegistry` + persistence |
| `CancelTask` | A2A § 9.4.5 | replaces v0.1.0 `tasks/cancel` |
| `SubscribeToTask` | A2A § 9.4.6 (new in v1.0.1) | re-subscribe to an existing non-terminal Task's SSE |
| `CreateTaskPushNotificationConfig` | A2A § 9.4.7 | item #6 |
| `GetTaskPushNotificationConfig` | A2A § 9.4.7 | item #6 |
| `ListTaskPushNotificationConfigs` | A2A § 9.4.7 | item #6 |
| `DeleteTaskPushNotificationConfig` | A2A § 9.4.7 | item #6 |
| `GetExtendedAgentCard` | A2A § 9.4.8 | returns the AgentCard with the standard `pushNotifications: true` capability after item #6 lands |
| `_shim/conversation/reset` | a2a-shim extension | item #8 — uses `_shim/` prefix to flag non-standard origin |

Wire shape replacements (per ADR 0005):

- `Part` discriminator: drop `type` tag, use member-presence (`untagged`
  enum with `Text { text }` first).
- SSE event: wrap inner in `statusUpdate`/`artifactUpdate` object
  rather than tag with `kind`.
- File fields rename: `bytes` → `raw`, `mimeType` → `mediaType`,
  `uri` → `url`, `name` → `filename`.

`a2a_shim_core::wire::message::Part`, `wire::sse::SseEvent`, and the
HTTP dispatcher in `a2a_shim_serve::http` are all rewritten. All
v0.1.0 round-trip tests in `a2a-shim-core` are re-baselined against the
new payload literals.

## 2. Item 1 — Multi-Modal Part ↔ ContentBlock

**Authoritative:** ADR 0006.

Spec § 2.9 from v0.1.0 (the
`session/update → A2A event translation` table) gains five new rows
for the non-Text variants per ADR 0006. The translation lives in a new
module `a2a_shim_core::wire::message::translate` exposing two pure
functions:

```rust
pub fn a2a_to_acp(parts: &[Part], caps: &PromptCapabilities) -> Vec<ContentBlock>;
pub fn acp_to_a2a(blocks: &[ContentBlock]) -> Vec<Part>;
```

Capability gating uses the `PromptCapabilities` returned by the agent
on `initialize`. The Serve Shim caches it on `acp_client` and exposes
via `ServeState::prompt_capabilities()`.

### Size cap

The CLI gains `--max-part-bytes <BYTES>` (default 10 MiB). Enforced:

- **Serve Shim:** axum `RequestBodyLimit` layer wraps the JSON-RPC
  router so a request body larger than the cap returns HTTP 413 before
  deserialization. A successfully deserialized `Part` whose `raw`
  field exceeds the cap individually returns `INVALID_PARAMS` (a
  smaller request body but a single oversized part).
- **Client Shim:** the inbound SSE pump in `outbound::stream` rejects
  any `artifact-update` whose individual Part exceeds the cap.

## 3. Item 2 — G2 Streaming

**Authoritative:** extends ADR 0003 (Client Shim heartbeat).

ADR 0003's `notifications/progress` heartbeat carried a placeholder
counter in `params.message`. v1.1 replaces the placeholder with
**accumulated agent text**:

- The Client Shim's `Heartbeat` (in
  `a2a_shim_client::heartbeat`) gains a `last_text: parking_lot::Mutex<String>`
  field next to the existing summary.
- The `a2a_send` call handler's bridge-event consumer appends each
  arriving `artifact-update` text into `last_text`.
- The progress emitter packs the **last 200 characters** of
  `last_text` into `params.message` on every tick.

### Cadence policy

- **Idle / no text seen yet:** the existing 30-second cadence (ADR
  0003 default).
- **Streaming (text has arrived in the last 5 seconds):** accelerate
  to 1-second cadence so the progress feed actually feels live.
- **Threshold-based send:** in addition to the timer, fire a
  `notifications/progress` whenever 50 new characters have accumulated
  since the last emission. Whichever (50-char threshold OR 1-second
  timer) trips first wins.

### Field shape

```json
{
  "jsonrpc": "2.0",
  "method": "notifications/progress",
  "params": {
    "progressToken": "<from caller>",
    "progress": <monotone counter>,
    "total": null,
    "message": "<last 200 chars of accumulated agent text>"
  }
}
```

`progress` stays a monotone counter (ADR 0003); we do not try to
estimate "percent complete" since the agent doesn't tell us.

## 4. Item 3 — Persistence

**Authoritative:** ADR 0007.

The Serve Shim gains a `[server.persistence]` configuration block
(default `enabled = true`, `path = "./a2a-shim.db"`) and a new
`a2a_shim_serve::persistence` module wrapping `rusqlite` under
`parking_lot::Mutex<Connection>`. Restart recovery batch-loads up to
8 sessions concurrently via ACP `session/load`.

Updates to v0.1.0 spec sections:

- **§ 2.6** (Session lifecycle): adds the "restart recovery" path —
  on Serve start, persisted conversations are re-attached via
  `session/load` before HTTP traffic begins.
- **§ 2.13** (v1.1+ TODO Anchors): items moved from "v1.1 TODO" to
  "shipped in v1.1": `session/load + session/resume`, `Conversation
  persistence`.
- **CONTEXT.md `Conversation`**: the "best-effort continuity" hedge
  weakens; with persistence default-ON, restart is now a recoverable
  event (was loss-on-restart in v0.1.0).

## 5. Item 4 — `caller_id` Partitioning

**Authoritative:** extends ADR 0004 (flat-namespace decision); new
config block defined here.

Three caller-id source paths, in priority order:

1. **HTTP request header** `X-A2A-Caller-Id` (if set and config allows
   header-source).
2. **Message metadata key** `x-a2a-shim/caller_id` in
   `SendMessage.params.message.metadata` (if set).
3. **Config default** `[server.caller_identity].default_caller_id`
   (default `"anonymous"`).

Configuration:

```toml
[server.caller_identity]
enabled = false                          # default OFF (v0.1.0 behavior)
default_caller_id = "anonymous"
trust_header = true                      # honor X-A2A-Caller-Id
```

When `enabled = false`, the ConversationMap key remains `String`
(just `conversation_id`). When `enabled = true`:

- Key becomes `(caller_id, conversation_id)` — same `conversation_id`
  under different callers now refers to different sessions.
- `ConversationLost` (item #5) compares both halves.
- Persistence schema's `caller_id` column (already reserved in ADR
  0007 schema v1) is populated from the resolved source path.

Client Shim adds an optional `caller_id: string` argument to the
`a2a_send` tool schema. When present, it is forwarded as the
`x-a2a-shim/caller_id` metadata key on outbound `SendMessage`.

## 6. Item 5 — `conversation_mode`

The `a2a_send` tool schema gains an optional `conversation_mode:
"new" | "continue" | "auto"` argument (default `"auto"`).

Semantics on the Serve Shim side (mapping into `ConversationMap` ops):

| mode | conversation exists? | Behavior |
|---|---|---|
| `auto` | yes | Reuse (current v0.1.0 behavior) |
| `auto` | no | Create |
| `new` | yes | Reject — `INVALID_PARAMS` with `_meta.error.kind = "conversation_exists"` |
| `new` | no | Create |
| `continue` | yes | Reuse |
| `continue` | no | Reject — `isError: true` tool result with `_meta.error.kind = "conversation_lost"` |

The `ConversationLost` wire shape (Client Shim → Host):

```json
{
  "isError": true,
  "content": [{ "type": "text", "text": "Conversation 'alice/x' no longer exists. The agent has lost context; start a new conversation or use mode='auto' to create one." }],
  "_meta": {
    "error": {
      "kind": "conversation_lost",
      "message": "Conversation 'alice/x' no longer exists on the remote agent.",
      "remote_task_id": null,
      "conversation_id": "alice/x"
    }
  }
}
```

New `ErrorKind::ConversationLost` and `ErrorKind::ConversationExists`
variants added to `a2a_shim_core::error::normalize`.

## 7. Item 6 — Push Notifications

**Authoritative:** ADR 0008.

New JSON-RPC methods (PascalCase per ADR 0005):
`CreateTaskPushNotificationConfig`, `GetTaskPushNotificationConfig`,
`ListTaskPushNotificationConfigs`, `DeleteTaskPushNotificationConfig`.
Wire shape per Spike C findings in
[`verify-v1.1/REPORT.md`](../../../verify-v1.1/REPORT.md).

Configuration:

```toml
[server.push_notifications]
enabled = true                           # default ON
max_attempts = 3                         # ADR 0008 retry policy
backoff_base_secs = 1
backoff_factor = 3
permanent_failure_threshold = 10         # delete config after M consecutive 4xx
http_connect_timeout_secs = 5
http_request_timeout_secs = 10
```

AgentCard now advertises `capabilities.pushNotifications = true`
(was `false` in v0.1.0).

New error codes:
- `PUSH_NOTIFICATIONS_NOT_SUPPORTED = -32030` — returned when push
  methods are called and `[server.push_notifications].enabled = false`.

## 8. Item 7 — Prometheus `/metrics`

The Serve Shim gains a `GET /metrics` route emitting Prometheus
text-format metrics via `metrics` + `metrics-exporter-prometheus`.

Configuration:

```toml
[server.metrics]
enabled = true                           # default ON
# `path` is fixed at /metrics; mounted on the same listener as A2A
```

The Client Shim has no metrics endpoint (would violate the stdio
discipline — stdout is the MCP transport).

### Core metrics

| Name | Type | Labels | Source |
|---|---|---|---|
| `a2a_shim_messages_total` | Counter | `method`, `status` (`ok`\|`err`) | one inc per inbound JSON-RPC call |
| `a2a_shim_conversations_active` | Gauge | (none) | derived from `ConversationMap` size |
| `a2a_shim_tasks_active` | Gauge | `state` | counts non-terminal Tasks in `TaskRegistry` |
| `a2a_shim_task_duration_seconds` | Histogram | `terminal_state` | observed on every terminal transition |
| `a2a_shim_outbound_request_duration_seconds` | Histogram | `endpoint`, `status_class` | Client Shim outbound; only emitted by Client (so Serve `/metrics` won't show it) |
| `a2a_shim_push_deliveries_total` | Counter | `status` (`success`\|`retry`\|`dropped`) | item #6 worker |

`endpoint` and similar high-cardinality labels are hashed to bounded
buckets via `a2a_shim_core::metrics::hash_label` (a small 32-bucket
mod-N hash) to keep Prometheus storage sane.

## 9. Item 8 — `_shim/conversation/reset`

Custom JSON-RPC method outside the A2A spec; namespaced under
`_shim/` to flag non-standard origin.

**Request:**

```json
{
  "jsonrpc": "2.0",
  "id": <any>,
  "method": "_shim/conversation/reset",
  "params": { "conversation_id": "alice/x" }
}
```

**Response (success):**

```json
{
  "jsonrpc": "2.0",
  "id": <same>,
  "result": {
    "cleared": true,
    "cancelled_task_ids": ["t-123", "t-456"]
  }
}
```

`cleared = true` means a conversation entry was found and removed.
`cleared = false` means no such conversation existed (idempotent
DELETE semantics; not an error).

**Side effects on `cleared = true`:**

1. All active (non-terminal) Tasks under this conversation transition
   to `Canceled` via `TaskRegistry::cancel`. Their `task_id` strings
   collect into `cancelled_task_ids`.
2. The ACP session for this conversation is sent `session/cancel`
   (best-effort; logged on failure).
3. The conversation row is DELETEd from SQLite (ADR 0007 schema's
   CASCADE removes tasks and push configs too).
4. The in-memory `ConversationMap` entry is removed.

If `[server.caller_identity].enabled = true`, the request can include
optional `caller_id` to disambiguate when the same `conversation_id`
exists under multiple callers. If absent, defaults are applied per
§ 5 (item #4).

No new error code — invalid params returns the standard
`INVALID_PARAMS = -32602`.

## 10. New Error Codes Summary

Added in v1.1, all in the JSON-RPC server-defined range:

| Code | Constant | Meaning |
|---|---|---|
| `-32011` (existing) | `CONVERSATION_LIMIT_REACHED` | unchanged from v0.1.0 |
| `-32012` (new) | `CONVERSATION_EXISTS` | mode=`new` rejected an existing id |
| `-32013` (new) | `CONVERSATION_LOST` | mode=`continue` missed (this is the JSON-RPC envelope shape; Client Shim renders `isError`+`_meta.error` per item #5) |
| `-32030` (new) | `PUSH_NOTIFICATIONS_NOT_SUPPORTED` | push methods called while disabled in config |
| `-32031` (new) | `INVALID_PUSH_NOTIFICATION_CONFIG` | malformed `PushNotificationConfig` payload |

## 11. Operating Notes (v1.1 deltas)

`docs/operating-notes.md` is updated with sections for:

- **Persistence:** how to back up the SQLite file, when to delete it,
  schema migration story, restart-recovery batch concurrency tuning.
- **Push notifications:** webhook firewall implications, retry/drop
  semantics, idempotency-key headers.
- **Metrics:** scraping interval recommendations, label cardinality
  caveats, mapping `task_duration_seconds` percentiles to SLOs.
- **caller_id:** trust model when `trust_header = true` (the operator's
  reverse proxy MUST authenticate the caller and set the header — the
  shim does not validate it).
- **Wire upgrade:** v0.1.0 wire is gone; v0.x A2A clients incompatible.

## 12. Out of v1.1 Scope (carry to v1.2)

- Elicitation bridging (ACP `elicitation/create` → A2A `input-required`
  Task).
- Permission `passthrough` strategy.
- H2 — concurrent `a2a_send` per MCP session.
- Per-conversation ACP Agent isolation.
- Mesh discussions (ADR 0002 F2 deferral).
- Per-conversation `SessionMode` persistence (re-apply mode on restart).
- Push notification delivery for artifact-updates (opt-in flag).
- Config hot-reload via SIGHUP.
- OpenTelemetry tracing export.
